# Lab Node Agent

Реализованы read-only Proxmox adapter, CLI `lab-node-agent` и служба `python -m lab_node_agent.service`. Отдельный Python-пакет без runtime-зависимостей, с собственным lockfile для тестов. Читает inventory по проверенному HTTPS с API token; не изменяет гостей. Служба отдаёт снимок только через mTLS с закреплённым сертификатом клиента.

Служба, опрос с VPS и pull-updater установлены на физическом узле; проверенные шаги описаны в [гайде транспорта](../../docs/node-transport.md) и [гайде автообновления](../../docs/node-auto-update.md). Типизированные команды изменения гостей, durable receipts и применение учебных сетей ещё не реализованы; произвольного shell API нет.

[Подготовка установки и границы inventory](../../docs/proxmox-agent-first-install.md).

[План реализации](../../docs/implementation-plan.md).

Wheel 0.3.0 также содержит [локальную диагностику LVM-thin](../../docs/proxmox-storage-probe.md). Она запускается администратором отдельно и не меняет права или поведение установленной службы.

Начиная с 0.8.0 снимок дополнительно содержит имена и порты Linux bridges, прочитанные из Proxmox API. При недоступности этой части остальные наблюдения сохраняются, а в `limitations` появляется `NETWORK_INVENTORY_UNAVAILABLE`. Наличие моста без физического порта само по себе не подтверждает изоляцию; `admission_ready` остаётся `false`.

Для будущей сверки задач добавлено внутреннее чтение конфигурации конкретной QEMU VM или LXC по типу и числовому VMID. Метод не публикуется в mTLS endpoint и не меняет гостя; произвольный путь Proxmox API передать ему нельзя. Признание машины принадлежащей Lab Manager потребует проверки метки владения и сохранённой записи в БД, а не одного совпадения VMID.
