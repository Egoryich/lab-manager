# Постоянные записи занятия и машин

Миграция `0008_runtime` добавляет идентичности `EnvironmentRun`, `Runtime`, `RunRuntime`, `ProviderRuntimeBinding` и `RuntimeDisk`. Это схема для будущего запуска, а не команда создания гостя. Пользовательские кнопки и операции Proxmox останутся выключенными до проверенного admission, сетевых правил и доступа Guacamole.

`Runtime` принадлежит окружению и сохраняется между парами. В новом `EnvironmentRun` связываются те же Runtime, поэтому остановка занятия не создаёт новые диски. У каждого действующего студента в окружении может быть только одна машина, у преподавателя — одна Demo. После подтверждённого удаления машины запись получает tombstone; новое вступление студента с новой membership generation не восстанавливает старые данные.

`ProviderRuntimeBinding` хранит VMID и ownership marker отдельно от доменного UUID. Уникальность VMID действует в пределах node. `RuntimeDisk` фиксирует принадлежащий Runtime том по Proxmox storage ID и provider reference; неизвестный том нельзя считать своим по совпадению имени. Составной внешний ключ запрещает привязать binding или диск к Runtime другого node. `RunRuntime` запрещает включить в занятие машину другого окружения.

`EnvironmentRun.ERROR` остаётся незавершённым и блокирует новый Run до сверки. `STOPPED` означает подтверждённое завершение; только после него допускается новый Run. Отдельная бронь удерживает CPU/RAM до подтверждения остановки. Диски и сохранённая RAM QEMU продолжают учитывать постоянное место.

Следующая часть этого этапа: команда `start` с повторной проверкой прав и состава группы, атомарное бронирование ресурсов и подсетей, idempotent provisioning через Agent, подтверждение реальной сети и Guacamole, затем `stop` с QEMU hibernation/LXC shutdown. Пока Agent остаётся read-only и `admission_ready=false`, новые таблицы не превращаются в работающий запуск.
