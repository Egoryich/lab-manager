# Готовность после уточнений пользователя

Актуальная база: исходное ТЗ v2.0 и [принятые решения](decisions.md). Изменения пользователя имеют приоритет. Исходник не редактировался, его SHA-256 сохранён.

## Вопросы, на которые уже получены ответы

| Тема | Принято |
|---|---|
| Аккаунты | Локальная самостоятельная регистрация Student, восстановление через Admin; Teachers назначает Admin |
| Архив | SOFT_ARCHIVE: те же диски на Proxmox, те же студенты после разархивирования |
| Конец пары | VM hibernate-to-disk; LXC shutdown с сохранением файлов; после подтверждения CPU/RAM освобождаются |
| Полное завершение окружения | Явное удаление всех его Runtime и данных, с подтверждением |
| Исключение студента | Удалить его машины/данные во всех Environment этой Group; другие Group и account не затрагиваются |
| Преподаватели | Только свои группы/окружения/брони; нет co-teacher и обзора чужой работы |
| Demo | Одна Demo на Environment, у Teacher обязательно есть допустимый demo profile |
| Помощь студенту | Teacher своего Environment может подключаться; совместный просмотр/управление через Guacamole при подтверждённой поддержке |
| Интернет и сеть | Обычный Интернет допустим; template/profile задаёт on/off, ISOLATED/GROUP_LAN и учебные сегменты; management всегда закрыт |

| Storage | Новое выделение блокируется при 10% free и при нарушении абсолютного/прогнозного запаса |
| Backup и snapshots | Backup/export выключены; snapshots только Admin; VM state для hibernation учитывается отдельно |
| Питание | Tuya Cloud, PCIe PWR/RESET, Central Europe, команды известны; статус ПК ещё проверить |
| Развёртывание | С нуля: чистый Proxmox node, чистая VPS и существующий домен |

Календарь разрешён пользователем. Предложенная реализация в [bookings.md](bookings.md): первая подтверждённая транзакция резервирует нужный объём на интервал, свою бронь можно отменить. Квоты Admin сохраняются: это верхние пределы Teacher, не замена календарю.

## Что ещё нужно предоставить

- Характеристики CPU/RAM/дисков, будущий storage backend, ОС/ресурсы VPS, конкретный доменный адрес и доступные LAN подсети. Пользователь сообщит позже.
- Обезличенный реальный Tuya status response и подтверждение соответствия status datapoint питанию ПК; команды Power/Reset уже известны.
- Для первого релиза: численные длительности броней, запас времени на boot/hibernate и idle timeout. Они могут быть настройками Admin; архитектуру не блокируют.

## Что требуется проверить инженеру, а не заново выбирать пользователю

1. VM hibernation/resume на выбранном Proxmox/storage, включая node reboot и учёт state file. LXC сохраняет файлы, не открытые процессы.
2. Guacamole authentication/revoke и authenticated teacher assistance к тому же активному tunnel. Второй независимый SSH shell не считается просмотром того же терминала.
3. Root-гость не обходит host network isolation; private IP может показываться владельцу без публикации внешнего SSH/RDP.
4. Tuya timeout не вызывает повторную опасную команду; cloud success не выдаётся за power ON/READY.
5. Calendar reservations, активные allocations и постоянные диски не учитываются дважды; конец интервала не освобождает фактически работающую машину.
6. Membership deletion охватывает точные объекты только нужной Group, переживает частичный отказ и не восстанавливает удалённые данные при unarchive.

## Состояние реализации и среды

Документы и структура подготовлены; product code, migrations, lockfiles и executable Compose ещё отсутствуют. Последняя локальная проверка 2026-09-16: Node 24.16.0, npm 11.13.0, uv 0.9.8, Docker CLI 28.5.1; Docker daemon не доступен, Python 3.13+ не подтверждён. Эти наблюдения не являются новой проверкой текущего состояния компьютера.

Документ [deployment-from-zero.md](deployment-from-zero.md) показывает этапы установки, границы VPS/node/gateway и будущие артефакты поставки. Нельзя пока обещать одну работающую команду установки приложения или подтверждённую вместимость на 30 студентов.

Можно переходить к D1 и реализации текущей доменной модели. Конкретные сетевые адреса, storage layout и мощности не фиксируются до inventory; доступ к реальным серверам пока не выполнялся.
