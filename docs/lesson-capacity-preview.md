# Предварительный расчёт занятия

Администратор на экране «Серверы» выбирает учебное LVM-thin хранилище и запасы RAM для Proxmox, инфраструктуры и безопасности. `PUT /api/admin/nodes/{node_id}/resource-policy` принимает ожидаемую версию настройки: параллельные изменения не перезаписывают друг друга. Настройка создаёт строку ledger, которая позже сериализует бронирование на этом узле. Смену storage ID при уже учтённых дисках API запрещает.

Преподаватель выбирает интервал на карточке окружения. `GET /api/environments/{id}/lesson-preview` пересчитывает активный состав группы и демо-машину из закреплённых версий профилей и размеров. Для каждого настроенного узла он сопоставляет свежий снимок, постоянные дисковые обязательства и пересекающиеся брони. Ответ показывает причины недоступности, не раскрывая занятия других преподавателей. Интервал ограничен 24 часами и горизонтом 90 дней.

Ответ **не создаёт бронь и не гарантирует место**: между просмотром и началом занятия состав группы, снимок или чужие брони могут измениться. Операция бронирования должна повторить проверку внутри транзакции с блокировкой ledger и группы. Нынешний Proxmox agent продолжает сообщать `admission_ready=false`; до завершения сверки владения машинами, сети и Guacamole предварительный расчёт покажет отказ.

Исправлено правило ledger: одно окружение нельзя одновременно забронировать на двух узлах. Если для окружения уже зарезервированы диски, новый урок остаётся привязан к тому же узлу. Это сохраняет обещание «те же машины и данные на следующей паре».

Резервы RAM задаёт администратор, а CPU-бюджет и минимум 10% свободного места выставляются системой. Это не размеры отдельных машин и не лимиты преподавателя: размеры хранятся в окружении, права — в политике преподавателя, а фактическая вместимость зависит от узла и расписания.

Первый дополнительный запрос к `/openapi.json` вернул 404 из-за неверного пути в выданной команде. Правильный путь приложения — `/api/openapi.json`; ошибки Python после 404 были следствием пустого входа, а не сбоя API. Исправленная read-only проверка успешно напечатала `PASS: новые API доступны`:

```bash
python3 - <<'PY'
import json
from urllib.request import urlopen

with urlopen("http://127.0.0.1:18000/api/openapi.json", timeout=10) as response:
    paths = json.load(response)["paths"]

required = {
    "/api/admin/nodes/{node_id}/resource-policy",
    "/api/environments/{environment_id}/lesson-preview",
}
assert required <= paths.keys()
print("PASS: новые API доступны")
PY
```

Эта проверка подтверждает наличие маршрутов в работающем выпуске, но не выполнение авторизованного сценария в браузере и не успешное бронирование. [CI выпуска](https://github.com/Egoryich/lab-manager/actions/runs/37117281326) прошёл, включая PostgreSQL integration tests, браузерные сценарии и публикацию образов.
