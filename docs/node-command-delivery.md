# Доставка команд LXC с VPS

Миграция `0009_commands` и worker добавляют постоянную запись команды до
сетевого запроса к Proxmox. У каждой команды есть UUID, привязка к операции
занятия, конкретной машине и узлу, точный JSON, состояние, время первой
попытки и ответ агента. В один момент у машины может быть только одна
незавершённая команда.

Worker перед отправкой один раз фиксирует `ATTEMPTED` в PostgreSQL. После
этого он может только читать ответ агента по UUID; повторный POST он не
отправляет. При потере ответа, отсутствии записи в журнале агента или
неудаче задачи Proxmox команда остаётся для ручной сверки. Это может оставить
занятие незапущенным, но не создаст второй контейнер поверх первого.

Пока ни API, ни интерфейс не создают строки `node_commands`. Выход к
командному endpoint Proxmox не активируется одной только миграцией. Перед
первым реальным занятием отдельно нужны: выделенный write token Proxmox с
минимальными ACL, включение журнала агента, настройка доступной Guacamole
сети, проверка резерва CPU/RAM/disk и полноценное создание операции занятия.

Проверка после автообновления VPS: `SELECT version_num FROM alembic_version`
должна вернуть `0009_commands`; API и worker должны быть healthy. Не следует
вручную вставлять команды в БД: их будет формировать только транзакция запуска
занятия вместе с правами, резервом и снимком состава группы.

Аппаратная проверка исходного пути уже выполнена на Proxmox: временный Debian
13 LXC создался в `student-lvm`, запустился, подтвердил SSH, остановился и был
удалён вместе с диском и изолированным мостом. Предупреждение о systemd 257
не помешало запуску; включать LXC nesting для этого не потребовалось.

При запуске созданного LXC агент сначала проверяет работающую сетевую защиту,
затем снимает `link_down=1` с `net0` через API Proxmox и только после повторной
сверки конфигурации отправляет команду запуска. Для этого выделенному write
token требуется `VM.Config.Network` на управляемых VMID в дополнение к правам
создания и питания. Пока отдельный допуск SSH не применён, защитные правила
Lab Manager блокируют трафик учебного моста. Ошибка изменения `net0` оставляет
команду в состоянии для ручной сверки; повторный POST не выполняется.
