# Проверенный цикл одноразового Debian LXC

04.10.2026 на целевом Proxmox проверен первый аппаратный цикл для
`debian-13-standard_13.6-1_amd64.tar.zst` и выделенного thin storage
`student-lvm`. Тест создал unprivileged LXC с диском 4 GiB и сетевым линком
`link_down=1` на временном закрытом мосту. Контейнер запустился, внутри
подтверждены Debian и наличие `sshd`; затем штатно остановился. Proxmox удалил
контейнер и его том, а локальный helper удалил пустой мост. Это доказывает
операции на данном узле, но не доступ через Guacamole и не полный урок.

Первая попытка распаковки не прошла из-за `umask 077` у вызывающего root shell:
каталог `/var/lib/lxc/<vmid>/rootfs` оказался недоступен для
`lxc-usernsexec`. Тест теперь использует `umask 022` непосредственно перед
`pct create`. После второй попытки Proxmox вернул описание с завершающим
переводом строки; проверка маркера владения теперь удаляет только `CR/LF` на
конце строки. Не ослаблять проверку самого маркера.

Перед повтором одноразового теста проверяют, что выбранный VMID свободен,
конфигурации и тома отсутствуют, mount под `/var/lib/lxc/<vmid>/rootfs` нет.
Пустые каталоги после неудачной распаковки удаляются `rmdir`, который не
удалит содержимое. После сбоя **не запускать тест снова**, пока не осмотрены
VMID, том и мост. При успешном цикле полезные проверки на хосте:

```bash
vmid=НОМЕР_ОДНОРАЗОВОГО_LXC
pct status "$vmid" # до запуска: stopped; после: running
pct exec "$vmid" -- sh -c '. /etc/os-release; test "$ID" = debian; command -v sshd'
pct shutdown "$vmid" --timeout 60
test "$(pct status "$vmid")" = 'status: stopped'
# Перед pct destroy повторно проверить точный маркер владения и storage.
pct destroy "$vmid" --purge
```

На целевом шаблоне Proxmox предупредил о systemd 257 и возможной нужде во
`nesting`. В этом тесте LXC стартовал без включения nesting. Для будущих
профилей с такой функцией требуются отдельные проверки безопасности; глобально
включать её из-за предупреждения не нужно.

Следующий шаг — связать создание и остановку постоянных Runtime с операцией
VPS и подтверждением Proxmox task. Отдельно необходимы маршрутизируемый доступ
`guacd` к SSH внутри гостя, закрытый входящий путь для студентов и browser
session через Apache Guacamole. Пока эти шаги не проверены, учебный цикл не
считается готовым.
