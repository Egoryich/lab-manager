## Уточнения без изменения пользовательского намерения

«Все ресурсы освобождены» после пары означает CPU/RAM и активный слот. Сохраняемые disks и файл RAM для hibernation продолжают занимать storage. Иначе продолжение работы с прежними данными невозможно.

«Всё за студентом» трактуется в пределах удаляемой Group: пользователь может состоять в нескольких независимых группах. Секреты его удалённых машин также уничтожаются; аудит и tombstones сохраняются без содержимого дисков. Перед подтверждением преподаватель видит именно перечень уничтожаемых данных. Неизвестные/чужие volumes по совпадению имени не удаляются.

Квоты и бронь — разные проверки. Квота Admin ограничивает максимальный объём одного Teacher, бронь определяет доступность этого объёма в конкретное время. Пока пользователь не отменял систему квот из §8, она остаётся. Actor и владелец Environment в текущем продукте совпадают для обычного преподавательского действия.

Обычная видимость private IP гостя и root-доступ не разрешают чтение Proxmox, Agent, BMC, secret keys, других Teacher/Environment. Общая сеть создаётся только внутри учебных границ и разрешений Admin.

Root внутри гостя может определить публичный адрес, с которого VPS выпускает трафик в Интернет, через внешний сервис. Требование DEC-18 означает отсутствие доступа к внутренним адресам и сервисам инфраструктуры, а не невозможность узнать публичный egress IP.

## Оставшиеся данные и инженерные проверки

- **CHECK-PERSISTENCE:** решение принято, но hibernate/resume на выбранной версии Proxmox/storage, поведение после reboot и расход места требуется проверить на стенде.
- **CHECK-TUYA:** transport Cloud, регион, команды и PWR/RESET известны из сообщения пользователя. Нужен реальный status payload, его freshness и соответствие состоянию ПК; плата online не означает компьютер ON. Это проверка интеграции, а не повторный выбор устройства.
- **SNAPSHOTS:** вопрос закрыт: только Admin. Все старые teacher permissions snapshots сохраняются в справочнике исходного ТЗ, но заблокированы системной policy текущей поставки.
- **OPEN-INFRA:** характеристики, конкретное доменное имя, ОС VPS, объём/тип storage, адреса LAN и доступный канал Интернет. Их пользователь обещал сообщить позже.

Политика завершения при сбое hibernation не должна молча уничтожать несохранённую RAM. Пользователь разрешил «гасить VM» при неисправности; это отдельный явно видимый force-stop с потерей текущей RAM, а не успешное сохранение состояния.
