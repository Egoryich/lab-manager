# Итог подготовки к разработке

Обновлено 2026-09-17 после ответов пользователя. Объём работы — анализ и подготовка проекта; функциональная реализация Lab Manager ещё не начата. [17 принятых уточнений](decisions.md) имеют приоритет над неизменённым исходным ТЗ.

## Подготовлено

- Прочитано всё основное ТЗ v2.0, 76 разделов. Сохранена побайтовая копия под каноническим именем [LAB_MANAGER_CODEX_SPEC.md](../LAB_MANAGER_CODEX_SPEC.md); происхождение и SHA-256 записаны в [spec-source.json](spec-source.json). Git attributes исключают преобразование окончаний строк у этой копии.
- Спроектированы размещение VPS/node/gateway, границы модулей, provider interfaces, доменные сущности, state machines и фоновые операции с восстановлением после сбоев.
- Описаны права/лимиты, независимые Teacher, destructive kick в пределах Group, local signup/Admin recovery, календарь, teacher assistance, обязательная Demo, VM hibernate/LXC shutdown, SOFT_ARCHIVE, Admin snapshots и отключённый backup.
- Все 76 исходных разделов связаны с проектными документами в [requirements.json](requirements.json); [requirements-updates.json](requirements-updates.json) связывает 17 новых решений с изменяемыми разделами и проверками. Теперь 60 сценариев и BUILD-01/02/03 для стека, состава репозитория и установки с нуля.
- Создана структура 15 каталогов приложений, packages, инфраструктуры, migrations и tests с границами ответственности. Зафиксированы порядок разработки и критерии завершения этапов.
- Написаны [инструкция установки с нуля](deployment-from-zero.md) и [интеграция Tuya Cloud](power-tuya.md). Остались hardware inventory и реальная привязка status datapoint платы; продуктовые ответы зафиксированы в [readiness.md](readiness.md).

## Выполненные проверки

Команда: `node tools/validate-preparation.mjs` из корня репозитория.

Результат проверки подготовки: **PASS**. Проверены SHA-256 копии ТЗ; все 76 исходных разделов и 17 уточнений; существование связанных документов; ссылки на 60 ACC и три build gates; наличие всех 45 исходных API routes и 20 имён permissions с уточнённой семантикой; 15 каталогов; локальные Markdown-ссылки. Отдельно проверен синтаксис Node-скрипта. Запрещённый DELETE /api/storage/cleanup/all не считается маршрутом к реализации.

Первичная подготовка прошла независимую сверку до уточнений пользователя. После новых ответов документы пересмотрены: co-teacher исключён, backup disabled, snapshots Admin-only, hibernation state включён в storage budget, добавлены bookings/assistance и exact deletion scope. Это проектные проверки, не выполненные интеграционные испытания.

Проверка не оценивает доступность удалённых ссылок, не доказывает безопасность работающей системы и не заменяет продуктовые тесты. Все продуктовые сценарии и BUILD gates имеют статус **NOT_RUN**, реализация — **NOT_STARTED**.

## Что пока не готово

Нет исходного кода сервисов, dependency lockfiles, миграций, исполняемого Compose и CI pipeline. Их создание и проверка относятся к D1 и последующим этапам, описанным в [implementation-plan.md](implementation-plan.md). Текущее содержимое не является запущенным приложением или проверенной средой разработки.

Docker CLI доступен, но daemon не отвечал в текущей сессии. Наличие доступного Python 3.13+ не подтверждено. Установки, изменение системных прав, запуск служб и обращение к реальным VPS/Proxmox не выполнялись.

Пользователь уже определил регистрацию/recovery, SOFT_ARCHIVE, Internet policy, обязательную Demo, teacher isolation, Tuya Cloud и VM/LXC persistence. Характеристики оборудования, адреса и конкретный домен будут сообщены позже. Реальные Tuya status mapping, Guacamole shared tunnel и hibernate/resume совместимость проверяются на стенде; не объявляются готовыми на основании документации.

Следующий рабочий этап — D1: воспроизводимая сборочная среда и проверка критических интеграций, параллельно с реализацией независимых частей домена. Не требуется заменять выбранную архитектуру после первой вертикали.
