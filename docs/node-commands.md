# Команды LXC на узле: выключены до отдельной активации

Wheel `0.12.0` добавляет в существующий mTLS endpoint узкие команды
`LXC_CREATE`, `LXC_START`, `LXC_SHUTDOWN` и чтение их состояния. По умолчанию
`commands_enabled=false`: действующая служба продолжает только выдавать
инвентаризацию. Установка wheel автоматическим updater **не создаёт гостей**,
не меняет firewall, не выдаёт новый Proxmox token и не разрешает доступ к
учебным сетям.

Для активации позже понадобятся отдельный Proxmox API token с проверенными
минимальными ACL, постоянный каталог журнала, root-owned настройки узла и
systemd drop-in с дополнительным `LoadCredential` и `ReadWritePaths`.
Создавать token с широким ACL только ради прохождения теста нельзя. До
проверки конкретных разрешений PVE и отрицательных проб endpoint оставляем
выключенным. Существующий read-only token не расширяется.

Включённый endpoint принимает JSON до 16 KiB только от уже закреплённого
mTLS-клиента VPS. Команда обязана указать `node_id`, `operation_id`,
`runtime_id`, `generation` и VMID. Для создания дополнительно фиксируются
Debian template и storage из операторской конфигурации, размер, SSH public key
и сегмент. Мост должен иметь вычисляемое имя и alias локального сегмента и
оставаться выключенным. Гость создаётся unprivileged, остановленным, с
`link_down=1`, без дополнительных host mounts или произвольных параметров.

Перед Proxmox POST агент синхронно записывает `INTENT` в SQLite. Повтор с тем
же `operation_id` возвращает прежний receipt; повтор с изменённым содержимым
отвергается. Другая команда для того же VMID ждёт завершения или ручной сверки
предыдущей. Если ответ от Proxmox потерян, состояние становится `UNCERTAIN` и
команда автоматически **не повторяется**. Для `SUBMITTED` агент читает task
UPID; успех фиксирует только после проверки маркера, конфигурации и реального
состояния LXC. Неудачный task тоже требует сверки: после ошибки создания
Proxmox может оставить частичный ресурс.

HTTP-контракт для worker: `POST /v1/commands` возвращает receipt с кодом 202;
`GET /v1/commands/<operation_id>` читает и сверяет task. Строки shell,
произвольный URL/путь Proxmox, операции удаления и сетевые изменения через
этот endpoint отсутствуют. Список допустимых команд намеренно ограничен
первым LXC-циклом. Пока VPS worker не хранит командные receipts, не выполняет
повторную авторизацию преподавателя и не подтверждает Guacamole, включать
кнопку «Начать занятие» нельзя.

Проверенный аппаратный тест создания/старта/остановки Debian LXC описан в
[proxmox-lxc-smoke.md](proxmox-lxc-smoke.md). Командный endpoint на целевом
узле пока не активирован и не проверен; это отдельный этап развёртывания.
