# Запуск первой работающей части

Реализованы учётные записи, группы, каталог/политики и подготовка окружений с расчётом. Запуск машин, Guacamole, Tuya, календарь, транзакционное резервирование и агент ещё не реализованы. Запуск предназначен для разработки; публикация требует production-конфигурации.

## Требования

- Python 3.13, uv 0.9.8 или совместимый новый выпуск.
- Node.js 24 и npm.
- Docker с работающим Linux engine и Compose.

Все команды выполняются из корня репозитория. На Windows используйте `npm.cmd`, если политика PowerShell блокирует `npm.ps1`. При недоступном пользовательском кэше uv можно задать `$env:UV_CACHE_DIR="$PWD\.cache\uv"` и `$env:UV_PYTHON_INSTALL_DIR="$PWD\.cache\python"`.

## Первый запуск

```sh
node tools/init-dev.mjs
uv sync --locked
npm ci
docker compose up -d --wait
uv run alembic upgrade head
uv run python -m lab_manager.cli bootstrap-admin
```

Последняя команда запрашивает логин, имя и пароль администратора в терминале. Пароль не передаётся аргументом команды и не выводится. Повторное создание первого администратора блокируется. Никаких заводских аккаунтов и паролей нет.

Генератор создаёт `.env` с отдельными случайными ключами и паролем PostgreSQL. Существующий файл не перезаписывается. Не удаляйте его после создания данных: смена ключей без отдельной миграции сделает коды групп нечитаемыми и отзовёт сессии. PostgreSQL хранит данные в именованном Docker volume; обычная остановка контейнеров его сохраняет.

В двух терминалах:

```sh
uv run python -m lab_manager
```

В отдельном терминале запустите обработчик фоновых проверок:

```sh
uv run python -m lab_manager.worker
```

```sh
npm run dev
```

Откройте **http://localhost:5173**. Используйте именно этот адрес: проверка Origin намеренно не принимает другие имена хоста. API слушает 127.0.0.1:8000, PostgreSQL — 127.0.0.1:55432, Redis — 127.0.0.1:56379. Интерактивное описание API в development: http://localhost:8000/api/docs. Для изменяющих запросов Swagger необходим Origin и CSRF; удобнее проверять через UI или тесты.

## Проверить сценарий

1. Зарегистрировать будущего преподавателя через форму «Регистрация студента».
2. Войти администратором, открыть «Пользователи» и назначить этому аккаунту роль преподавателя. Это разрешает создание групп; права на машины пока не выдаются.
3. Преподавателю войти заново: смена прав отзывает старые сессии. Создать группу и получить шестизначный код.
4. В другом профиле браузера зарегистрировать студента, войти и ввести код. Повторный ввод не создаёт второго участника.
5. Преподавателю обновить группу: студент появится в списке. Другой преподаватель эту группу не видит.
6. Проверить закрытие приёма и замену кода. Уже вступившие студенты остаются в группе.

Восстановление: администратор проверяет личность человека, выдаёт одноразовый код в «Пользователях» и передаёт лично. Пользователь открывает «Забыли пароль?» и задаёт свой новый пароль. Код живёт 15 минут; выдача нового кода отменяет старый и отзывает прежние сессии. Коды не вставляются в URL и не сохраняются в журнал действий.

## Проверки

```sh
uv run ruff check apps/api tests migrations tools/*.py
uv run pytest tests/unit -q
uv run alembic check
uv run python tools/check-contract.py
npm run build
node tools/validate-preparation.mjs
```

Интеграционные тесты требуют запущенных PostgreSQL/Redis и явного переключателя:

```powershell
$env:LAB_RUN_INTEGRATION='1'
uv run pytest -q
```

На Linux: `LAB_RUN_INTEGRATION=1 uv run pytest -q`.

Тесты применяют настоящую миграцию в каждой отдельной схеме `lab_test_<uuid>` и удаляют только свою схему. Существующие таблицы приложения и аккаунты не трогают. Production-настройки отклоняются. Redis-ключи изолированы случайным ключом теста и истекают по TTL; `FLUSHDB` не используется.

Браузерные сценарии:

```sh
npx playwright install chromium
uv run python tools/run-e2e.py
```

Этот запуск создаёт собственную схему и временные аккаунты, поднимает API на 8001 и Vite на 5174, выполняет Playwright, затем останавливает свои процессы и удаляет тестовую схему. Скриншоты сохраняются в `artifacts/`, диагностика — в `test-results/`. Каталоги исключены из Git; диагностические трассы могут содержать данные тестовых сессий.

При изменении API обновить контракт: `uv run python tools/export-openapi.py`, затем `npm run generate`. В репозитории фиксируются OpenAPI, сгенерированные TypeScript-типы и оба lockfile. CI повторяет миграции, API-тесты, сборку и браузерные сценарии на Linux.

## Остановка и продолжение

На Windows после установки зависимостей и создания `.env` можно запустить весь локальный стенд одной командой:

```powershell
.\tools\start-dev.ps1
```

Скрипт запускает контейнеры PostgreSQL/Redis, применяет миграции и запускает API/worker/Vite в фоне. Адрес выводится только после проверки готовности API через frontend. Логи находятся в `.cache/dev-*.log`. Если порт занят, скрипт останавливается и не завершает чужой процесс. Для отдельного Docker config доступен параметр `-DockerConfig .cache/docker`. Это локальный запуск, не production-развёртывание.

После обновления выполните `uv run alembic upgrade head` и перезапустите API и worker. Для профилей: Admin → «Профили и права»: версия шаблона → профиль → политика с разрешениями, ненулевыми лимитами и demo → назначение Teacher. В группе появятся разрешённые student/demo профили, расчёт и создание подготовленного окружения. Описание шаблона ещё не импортирует образ Proxmox.

Остановите API и Vite через Ctrl+C, затем `docker compose stop`. Для продолжения: `docker compose up -d --wait` и снова запустите два приложения. Не используйте `down -v`, если хотите сохранить данные.

Развёртывание итоговой системы на пустых VPS/Proxmox описывается отдельно в [deployment-from-zero.md](deployment-from-zero.md). Наличие dev Compose и Dockerfile API ещё не означает готовность этого развёртывания.
