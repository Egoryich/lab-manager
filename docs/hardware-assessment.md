## Физический сервер

- Xeon E5-2673 v3: **12 физических ядер / 24 потока**. Потоки не приравниваются к физическим ядрам при резервировании.
- MemTotal 32 760 852 KiB = **31 993 целых MiB**. Swap не входит в гарантированный RAM-бюджет.
- Proxmox VE 9.2.0, pve-manager 9.2.20, Debian 13 — версии из документа; совместимость адаптера проверяется на стенде.
- Системный SSD 120 GB, служебный `local-lvm` около 63 GB. План: служебная VM Guacamole/guacd на SSD.
- Студенческий HDD 500 GB, `student-lvm` LVM-Thin около 456.3 GiB. Диски студентов, demo и RAM-состояние VM учитываются отдельно.
- Существующие **два тестовых LXC — внешние ресурсы**: тест Guacamole (диск 12 GiB на `local-lvm`) и тест студента (10 GiB на `student-lvm`). Пользователь подтвердил тестовое назначение 29.09.2026; это не разрешение удалять или переиспользовать их. Не импортировать автоматически и не помечать orphan. ID и адреса хранятся в локальном inventory.
- Headscale/Tailscale между VPS и Proxmox уже настроены, тестовая гостевая подсеть назначена. Изоляция management от учебных сегментов остаётся обязательным требованием и требует отдельной проверки.

### Уточнение по выводу команд от 29.09.2026

Источник — присланный пользователем вывод диагностики, не опрос работающего агента. `lscpu` подтвердил E5-2673 v3 (12 ядер / 24 потока), устранив расхождение с историческим Headscale-гайдом. `free -h` показал 31 GiB RAM, 29 GiB available и 4 GiB неиспользуемого swap. Доступная RAM в этот момент не является бюджетом для студентов: из неё ещё нужны резервы гипервизора и служебных компонентов.

Оба тестовых LXC остановлены; `qm list` пуст. Thin pool `local-lvm`: data 1.50%, metadata 1.63%; `student-lvm`: размер 456.32 GiB, data 0.21%, metadata 0.39%. Остановка освобождает вычислительные ресурсы, но не диски. Малый процент физического заполнения thin pool не отменяет учёта обещанного гостям логического места и будущих RAM-состояний. `local` и `local-lvm` нельзя складывать как независимые физические диски.

При 30 студентах × 512 MiB и одной demo 2048 MiB гостям нужно 17 408 MiB. При студентах × 1024 MiB и demo 2048 MiB уже нужно 32 768 MiB — больше наблюдаемой памяти, ещё без Proxmox и gateway. Поэтому 30 desktop VM одновременно не обещаем; лёгкие Linux LXC оцениваются отдельно по реальной нагрузке.

456.3 GiB × 90% ≈ 410.7 GiB — только арифметический верхний предел до дополнительных запасов, не доступное место. Нужны свежие thin data/metadata, logical quotas, CT 201, snapshots и hibernation states. Один HDD требует измерения задержек массового запуска/сохранения RAM.

## VPS

Пользователь сообщил: 1 vCPU 3–3.3 GHz, 1 GB RAM, 10 GB NVMe, канал 1 Gbit/s. Подтверждены Ubuntu 26.04.1 LTS и отдельный домен приложения. После первого запуска: RAM 955 MiB всего, 490 MiB available; корневая файловая система 8.6 GiB, свободно около 4 GiB; swap отсутствует. Это снимок первого запуска, не текущие измерения. Месячный traffic cap неизвестен.

29.09.2026 пользователь добавил ещё 1 GB RAM и перезагрузил VPS. Новый вывод `free -h`: всего 1.9 GiB, использовано 570 MiB, available 1.4 GiB; swap отсутствует. `df -h /`: 8.6 GiB всего, свободно 4.2 GiB (52% занято). Прежние 955 MiB относятся к конфигурации до расширения. Точное новое число MiB из округлённого `free -h` не выводится.

Запас памяти для добавления worker увеличился. Пригодность полного продукта под нагрузкой **не подтверждена**: нужны замеры RSS, одновременного входа, дискового запаса обновления и логов. Ограничения контейнеров не заменяют эти замеры: [Docker resource constraints](https://docs.docker.com/engine/containers/resource_constraints/).

Текущие меры: UI собирается вне VPS; Guacamole планируется на физическом сервере; API имеет максимум 5 соединений PostgreSQL без overflow. В VPS Compose один API-процесс и одна параллельная операция Argon2. Уже заданы memory limits: API 320 MiB, PostgreSQL 160 MiB, Redis 48 MiB, web 32 MiB; ограничены логи и настроен PostgreSQL. Четыре контейнера прошли первый запуск; worker ещё не развёрнут. Это не гарантия укладывания полного продукта в 1 GB.

Образы VM и диски не размещаются на VPS. Backups продукта отключены. Диск, исключённый пользователем из эксплуатации, не входит ни в один пул.

29.09.2026 после расширения VPS пользователь подтвердил запуск пятого контейнера — worker: 68.14 MiB при лимите 128 MiB. Все пять контейнеров healthy, локальная готовность API подтверждена. Детали замера и выполненные команды: [выпуск worker](vps-worker-rollout.md). Нагрузочная вместимость полного продукта по этому снимку не определяется.

## Границы расчёта в UI

Расчёт показывает гостевые RAM/vCPU/CPU-кредиты, диски и минимальное место для RAM QEMU. LXC не получает RAM-state файл. Demo учитывается всегда. Порог 10%, запасы гипервизора, текущие workloads и суммарные квоты по другим окружениям будет проверять scheduler на свежем inventory. Создание подготовленного окружения не резервирует ресурсы и не выполняет команды Proxmox.
