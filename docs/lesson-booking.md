# Бронирование учебного занятия

Преподаватель выбирает интервал в окружении и сначала смотрит предварительный расчёт. Если узел доступен, интерфейс отправляет `POST /api/environments/{id}/reservations` с идентификатором запроса, узла и увиденными версиями окружения и группы. API в одной транзакции блокирует ресурсный журнал узла, заново проверяет владельца, права, профиль, текущий состав группы и вместимость. Дисковый резерв сохраняется за окружением, а CPU/RAM — за интервалом занятия. Повтор того же запроса возвращает исходную бронь. Конфликтующие параметры с тем же идентификатором отвергаются.

Преподаватель видит свои активные и будущие брони через `GET /api/environments/{id}/reservations`. Будущую бронь можно отменить через `POST /api/reservations/{id}/cancel`. Если её диски ещё не созданы и других броней окружения нет, дисковый резерв снимается. Уже созданные диски отмена брони не удаляет.

Запись брони пока **не запускает** LXC. Если агент Proxmox не подтвердил готовность допуска, API отклоняет бронь, а интерфейс показывает причину. До подтверждения сети, принадлежности машин и дисковых обязательств занятие не предлагается к запуску.

После публикации выпуска VPS одна проверка на VPS:

```bash
cd /opt/lab-manager/repo
systemctl start lab-manager-update.service
python3 tools/verify-vps-network-foundation.py
docker compose --env-file .env.vps -f infra/vps/compose.yml \
  exec -T postgres psql -U lab -d lab -Atc \
  'SELECT version_num FROM alembic_version' </dev/null
```

Не копируйте секреты из `.env.vps`, ключи транспорта и токены Proxmox в отчёт о проверке.
