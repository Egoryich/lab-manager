# Состояние реализации — 2026-09-26

Срезы системы: учётные записи и группы; каталог, политики и подготовленные окружения. D1/D2/D3 в работе; ни один этап полного продукта не объявляется закрытым. Исходное ТЗ и принятые решения не сокращены.

## Реализовано

- FastAPI, SQLAlchemy, PostgreSQL, Redis; отдельная Alembic-миграция вместо создания таблиц при каждом старте.
- Локальная регистрация только Student; нормализованный логин, Argon2id, безопасные cookie-сессии и CSRF/Origin. Проверка роли и принадлежности объекта на backend.
- Первоначальный Admin через интерактивный CLI, без заводского пароля и публичной выдачи роли Admin.
- Назначение Teacher администратором и отдельный нормализованный override `can_create_groups`. Остальные права запрещены отсутствием реализованных команд; полная модель политик и лимитов ещё впереди.
- Восстановление через Admin: случайный одноразовый код на 15 минут, digest в базе, отзыв сессий и прежних кодов. Пользователь задаёт пароль сам.
- Создание группы владельцем, просмотр своих групп, получение и замена короткого кода, открытие/закрытие приёма, вступление и список участников. Студент не получает код приглашения и чужой roster.
- Транзакционная уникальность активных кодов и членства; блокировка группы сериализует вступление, смену кода и отключение приёма. Повторное вступление не создаёт дубликат. Изменения требуют актуальную version.
- Коды групп зашифрованы; короткие коды и session tokens проверяются по keyed digest. Аудит изменений сохраняется в той же SQL-транзакции, без паролей и токенов. Ошибки валидации не отражают секреты из запроса.
- Рабочий React UI для Student/Teacher/Admin, включая восстановление, пагинацию и ошибки. Генерируемый OpenAPI → TypeScript, типизированный клиент, отсутствие browser storage для токенов.
- Локальный Compose PostgreSQL/Redis, случайные секреты, lockfiles, API Dockerfile и CI-конфигурация. CI описан, но удалённый запуск GitHub Actions не выполнялся.

## Проверки

На Windows с Python 3.13.9, Node 24 и Linux-контейнерами PostgreSQL 17.6 / Redis 7.4.6:

- Unit: 7 тестов — защита секретов, валидация регистрации, запрет небезопасной конфигурации.
- PostgreSQL/Redis integration: 9 сценариев — auth/CSRF/logout, изоляция Teacher, student projection, повторные вступления, смена/закрытие кода, version conflict, одноразовое восстановление, отзыв прав, rate limit, коллизия кода и отказ Redis. Вместе с unit: **16 passed**.
- Конкурентный сценарий внутри integration: 30 разных студентов × 2 одновременных запроса, ровно 30 memberships и 30 событий вступления. Это не тест 30 работающих VM или Guacamole-сессий.
- `alembic upgrade head` и `alembic check`: миграция применена, расхождений с моделями нет.
- TypeScript/Vite production build, Ruff и сверка OpenAPI.
- Playwright Chromium: **2 passed** — Teacher → создание группы → регистрация/вступление Student → roster; Admin → роль Teacher → одноразовый recovery. Проверен мобильный экран 390px без горизонтального переполнения. Скриншоты просмотрены.
- Linux Docker API image собран из frozen lockfile, Python 3.13.15; непривилегированный UID 10001. Это проверка сборки, не проверка production-развёртывания.

BUILD-01/02/03 и полная матрица ACC остаются открытыми: частичные проверки не означают выполнение полного критерия. Исправлены выявленные тестами несовместимость Windows event loop с psycopg, обновление session query после входа и доступные названия полей формы.

Не выполнены подключения к целевой инфраструктуре, тесты гибернации, Guacamole assistance, Tuya, сетевой изоляции, storage и чистой production-установки. Характеристики оборудования получены; live inventory и status mapping платы ещё нужны. [Как запустить текущий код](local-start.md).

## Каталог и подготовка окружений

Миграция `0002_catalog` добавляет неизменяемые версии шаблонов/профилей, policy revisions, нормализованные permissions/limits, demo grants, назначения и Environment. Изменение/удаление версий блокируется PostgreSQL trigger. Пока каждая запись — самостоятельная версия; группировка по семействам и catalog lifecycle остаются задачей.

Admin регистрирует описание образа, профиль (RAM/vCPU/CPU-милликредиты/disk/network/Internet), политику с 20 разрешениями и 6 лимитами, обязательный demo grant и назначает её Teacher. Назначение проверяет expected_version. Старый индивидуальный `can_create_groups` имеет приоритет. Snapshots Teacher всегда DENY.

Teacher видит разрешённые профили и создаёт только свои подготовленные окружения. Версии student/demo закрепляются, повторный request_id возвращает тот же объект; изменённое тело — 409. Состав Run будет фиксироваться при запуске.

Расчёт разделяет Student и Demo, RAM, vCPU, целые CPU-милликредиты, disk bytes и RAM-state bytes QEMU. VM demo допустима по grant даже при запрете student QEMU. Интернет/общая сеть должны быть разрешены. UI сообщает: это **не бронь**, вместимость сервера/другие занятия не проверены, машины не созданы. Оценка сравнивает одно окружение с лимитами; суммарная занятость и max_active_environments относятся к будущему admission workflow.

На текущем коде: **18 backend-тестов прошли**, миграции применены и проверены, TypeScript/Vite build прошёл. Добавлены проверки demo exception, quota/network deny, идемпотентности, конкуренции, immutable trigger и assignment version. Два прежних браузерных сценария прошли; новый сценарий каталога требует завершения повторной проверки. Во время теста заполнение локального диска привело к ошибке записи PostgreSQL и недоступности Docker; данные не удалялись, очищены только восстановимые кэши.

Учтены [ограничения оборудования](hardware-assessment.md): ограничены параллелизм Argon2 и пул PostgreSQL. Продакшен-развёртывание на VPS 1 GB / 10 GB пока не подтверждено.
